Pinmony 是个人为了兴趣开发的 HarmonyOS 应用，主要用于学习、技术研究、界面探索和移动端体验测试。应用通过当前登录会话读取目标网站公开返回的页面或接口数据，并使用 ArkUI 提供原生界面。

## 功能

- 首页浏览推荐 Pin、图板和分类内容
- 搜索 Pin、分类、主题和相关内容
- 搜索结果首屏补读按已布局滚动区域判断：内容已可滚动时不因结果少于 20 条连续补读；短内容补读有次数及内容进展限制，滚动到底继续正常分页。SearchPagination 日志区分 viewport-fill 与 scroll-end；构建和离线回归不代表真机验收。
- 搜索筛选器保留当前搜索会话最后一个有效分页游标，分页结束后仍可读取筛选；更换搜索或刷新时清空，不复用其他查询的游标。入口、上下文拒绝、等待读取及选项数量记录为 SearchFilter 日志。
- 搜索结果的 Pin 卡片提供首页同款“选项”菜单：收藏、下载图片、查看更多、查看更少、分享链接；操作校验当前搜索完整地址（包含查询参数）和结果 Pin 身份，切换搜索后旧菜单失效。
- 查看 Pin 详情、作者、评论、相关推荐和支持的视频
- 浏览个人资料、已保存内容、图板和收件箱
- 收件箱提供图板邀请请求和“查看全部”；预览图板后重新校验当前邀请，邀请卡片支持上滑隐藏，再次预览重新显示。接受邀请以 BoardInviteResource/update 的 accepted 响应为准，显示加入提示并读取加入者头像。现有 HAR 未捕获拒绝写入，拒绝按钮暂不可用。
- 图板张数下的合作用户按钮进入原生合作用户页面，读取所有者、已接受与待接受邀请；邀请建议支持按姓名或用户名本地过滤，确认发送后提示“已发送 1 个邀请！”。权限页可保存已确认权限值 1 下的“邀请其他用户”开关；另一权限值与邮箱搜索未在提供的 HAR 中确认，暂未接入。
- 使用统一的应用内分享面板分享 Pin 和图板
- 图板标题栏不显示分享按钮；图板内照片菜单仍提供“分享链接”。
- 图板内照片菜单首项为“取消收藏”；校验当前账号与图板收藏副本并确认取消成功后提示“已取消收藏”，不提供撤回，未知写入结果需刷新核对。
- 取消收藏后保留图板当前列表和数量，卡片变暗并显示“已取消收藏，重新进入图板后移除”，禁止再打开该 Pin 或其菜单；退出图板重新进入后更新内容。图板照片菜单的“下载”位于第三项；从照片菜单进入“移至其他图板”后返回直接回到图板，整理入口仍保留选择 Pin 图层级。Pin 详情选项使用对应主题图标。图板底部加号复用“我的”的发布流程和反馈，准备发布上下文时仅加入当前文档对应的读取任务，关闭发布后恢复图板。
- Pin 帖子详情分享面板仅保留发送给联系人及其搜索、加载与结果反馈，不显示平台横排、复制链接和其他操作。
- 首页、图板内照片选项沿用 Pin 帖子选项的行间距：28vp 图标、14vp 图文间距、上下各 14vp 内边距，无额外行间空白；首页与 Pin 帖子选项中的分享文案为“分享链接”。
- 首页及图板内照片菜单标题为“选项”，按内容自适应高度，不显示横排平台。首页“查看更少”下的“分享链接”调用系统分享当前 Pin 链接；图板内依次显示“取消收藏”“移至其他图板”“下载”“查看更多”“分享链接”，移动复用已有流程且受编辑权限限制。详情、图板自身及联系人分享保留原流程。
- 保留页面状态、滚动位置、返回层级和加载状态


## 使用条件

2026-10-10：新增请求节制。原生业务请求遇到 429 遵循 Retry-After 并统一冷却，到期只允许一条必要 GET 确认恢复；不自动重放写入或积压请求。同文档在途 resource/get 读取合并，调用者独立取消；登录证据去重，手动会话重试间隔至少 5 秒，普通网络失败不作为登出。调试构建默认暂停首页提前分页、详情预取和资料 saved 预取，保留首屏及用户触发的读取；release 构建保留正常预取。网站自身请求及媒体读取不由该策略接管，未确认的安全验证合同不猜测接入，不保证账号不会受限。配置、回退与真机验收见 [原生网络说明](docs/NATIVE_NETWORK_NOTES.md#请求节制与反复真机测试2026-10-10)。

## 技术架构

- `entry`：应用入口、窗口生命周期、登录门禁、根页面、路由和跨页面协调
- `feature_home`：首页内容、分类、分页、缓存和首页状态
- `feature_search`：搜索输入、结果、分类、主题和搜索状态
- `feature_pin`：详情、评论、相关推荐、媒体、收藏和分享
- `feature_board`：图板页面、图板详情和图板内容
- `feature_profile`：个人资料、已保存内容、发布和整理流程
- `feature_inbox`：收件箱、会话、联系人和通知相关页面
- `feature_settings`：设置、账号信息、偏好和退出登录流程
- `common_session`：登录证据、会话和凭据适配
- `common_network`：原生 RCP 网络传输和请求生命周期
- `common_ui`：跨特性复用的 UI 组件和公共展示状态
- `common_foundation`：缓存、日志、任务登记和基础运行时能力

## 构建 HAP

在 PowerShell 中配置本机 HarmonyOS SDK 后执行：

```powershell
$env:DEVECO_SDK_HOME = '<HarmonyOS SDK 目录>'
$env:JAVA_HOME = '<DevEco Studio 安装目录>\jbr'
& '<DevEco Studio 安装目录>\tools\hvigor\bin\hvigorw.bat' --mode module -p module=entry assembleHap --no-daemon
```


## 隐私与会话

Pinmony 使用 ArkWeb 保留当前网站登录会话。原生网络按请求临时读取必要的 Cookie，并在需要时将 Set-Cookie 同步回当前 ArkWeb 会话。Cookie、CSRF、账号标识、访问令牌和响应凭据不会写入源码、仓库或持久化日志。

合作图板按当前响应的 collaborated_by_me 和 access/write 区分合作用户与所有者；删除图板和所有者设置仍限制所有者。图板与资料卡片传递 owner/collaborating_users 头像，后面的头像覆盖前面的头像。离开图板、移除成员及消息操作尚未接入。

合作图板消息入口：当前响应确认恰好两位成员且包含当前账号时，复用收件箱双人聊天流程；三人及以上仅提示不可用。成员资料、对方身份及消息响应均来自活动会话，不接入群聊。

受邀合作图板标题栏显示分享与三点入口；分享使用 Pin 分享半模态组件及当前会话的图板外部链接（invite_object=2），不使用系统分享面板。共享与收藏图板复用布局，仅成员、消息、权限差异独立处理。图板聊天先切换收件箱上下文，再打开双人会话。

共享图板三点菜单与自己的图板一致：编辑信息和设置、存档。受邀者编辑页仅显示合作用户与离开图板说明，未接入的离开操作不发送请求；名称、隐私及删除等所有者设置不向受邀者开放。存档复用既有已校验响应的流程。

邀请合作用户入口按当前响应开放：所有者，或 collaborated_by_me=true 且 collaborator_invites_enabled=true 的合作用户。权限修改仍只允许所有者；发送成功经 GraphQL 业务响应确认后显示提示条并将邀请按钮替换为已邀请。

boardEdit 响应缺少合作角色字段时，仅在当前图板 ID 与所有者 ID 均匹配的情况下保留同会话已确认的合作身份和头像；显式 false 不保留。已提供取消关注 HAR 中 unfollow 后 collaborated_by_me 仍为 true，因此不能把取消关注视为离开群组。

离开共享图板已接入当前 HAR 的 ApiResource/delete → v3_remove_board_collaborators，目标成员仅取当前会话 viewerId。只有当前图板 ID 匹配且响应 collaborated_by_me=false 才提示已离开并返回；不重放写请求，结果未确认时禁止重复提交。第二种合作权限的写入值尚未确认，仍不可切换。

受邀合作图板三点菜单在存档下增加取消关注，复用 HAR 确认的 ApiResource/delete → v3_unfollow_board；校验 code/status/endpoint/data=null 后提示已取消关注，合作身份不变。离开图板另有二次确认。新增收藏与评论 HAR 已确认权限 0 与 1 均可写入，对应所有事情与收藏评论；本轮未修改权限切换实现。

合作用户权限支持 HAR 已确认的两种值：0=做（几乎）所有事情，1=收藏并进行评论。仅所有者可选择权限及邀请开关，完成提交当前选择；校验图板 ID、权限值和邀请开关均与响应一致后更新，不按按钮点击推断成功。

搜索发现轮播和推荐主题已切换为轮播.har确认的当前会话 GraphQL：首屏 v3SearchTabHandlerQuery、分页 count/cursor。轮播使用 boardName、featuredBoardMetadata、boardUrl，点击进入原生 HDS 图板页；专题展示副标题、介绍、来源及可用封面。此流程不读取网页 DOM，无接口失败 DOM 回退。图板分享复用现有原生分享半模态，菜单仅开放已接入操作。

发布流程协调已归入 feature_profile 的 PinmonyPublishController，后台暂停取消旧读取，前台恢复仅回读状态；系统照片选择及跨页面返回由 Index 端口衔接。验证边界见 docs/PUBLISH_API_NOTES.md。

图板邀请状态与流程协调已归入 InboxStore / PinmonyBoardInvitationController，切页和后台废弃旧读取，前台恢复只回读状态，不重放接受请求；详见 docs/BOARD_INVITATION_ACCEPT_NOTES.md。

图板路由与快照归并已归入 PinmonyBoardStateController，初始加载超时随生命周期取消，保留列表与当前会话门禁；跨页面导航仍由 Index 协调，详见 docs/ARCHITECTURE.md。

评论、收藏选板和编辑 Pin 面板由 PinmonyPostPanelsController 统一协调读取、提交门禁及关闭；后台恢复只回读状态，不重放写入，系统图片及跨页面能力由 Index 端口提供。详见 docs/ARCHITECTURE.md。
